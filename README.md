# ClipPlus

Windows 剪贴板增强工具。捕获 → 本地落盘 → 通过网盘目录异地（非实时）同步。

- **快**：捕获走 `WM_CLIPBOARDUPDATE` 消息推送，空闲时 CPU 占用为 0，全程不轮询剪贴板。
- **省**：单进程，无 WebView / Electron / 运行时宿主。
- **异地同步**：历史存进一个「同步文件夹」里、每台机器自己那份 SQLite 库。扔进 OneDrive / 坚果云 / 任意网盘目录即可跨机器合并，A 机下午复制的东西，B 机晚上开机就能搜到。

## 同步是怎么工作的

**关键决定：每台机器每月一个 SQLite 库，且只有它自己那台机器会写。**

```
<OneDrive>/ClipPlus/
  3f9a2c81/2026-01/                     ← 机器 A 独占，已翻篇的月份，冻结
    clips.db                            ← 元数据 + 内联文本，每月一个
    1769000000001-4a77...b3.bin         ← 图片 / 超长文本的重负载
  3f9a2c81/2026-02/                     ← 机器 A 正在写的那一个月
    clips.db
    clips.db-journal                    ← 只在事务中间存在，提交后就没了
    1769000000000-9c1f...e0.bin
  7be44105/2026-02/                     ← 机器 B 独占
    clips.db
```

网盘客户端的同步语义是**文件级 last-writer-wins**。所以：

- ✅ 一个文件只有一个写者（`clips.db` 只由 machineId 那台机器写），**冲突在物理上不可能发生**，不需要锁、不需要协议、不需要服务器。
- ✅ 合并 = 打开每个库、按 stem 取并集。删除是一条 `DELETE`，跟着库文件传播，不需要墓碑文件。
- ✅ **只有当月那个库在被写**。月份一翻旧库就冻结，早就传完、永不再动，所以复制一条的代价是「重传当月这一个库」，不是重传整个历史。
- ❌ 不能开 WAL。`-wal` / `-shm` 得跟着 `.db` 一起搬，而 `-shm` 是本机专属的，别人拿到副本根本打不开；默认的 DELETE 日志让 `.db` 单文件自包含。
- ❌ 图片不进库。网盘搬的是整个文件，图进库就等于「每复制一条，把当月所有图片重传一遍」。图片和超长文本仍然拆到 `.bin`，列历史不碰那些几 MB 的文件。

`INSERT` 就是提交点：读方要么看到旧状态、要么看到新状态，不会读到半条记录——这正是以前 `.tmp` + 原子改名要保证的事。blob 依旧先于引用它的行写入，所以崩溃最多留下一个没人引用的 blob，而不是一条坏记录。

**别人那台机器的库可能正被客户端上传到一半。** 读方遇到打不开的库就跳过、保留上一次的快照，等下一轮（文件监听或 60 秒重扫）再读。失败模式是「暂时看不到那台机器今天的记录」，不是数据损坏，也不需要人工干预。

弹窗按实例分 tab：`全部` 是各机器混排，`本机` 只列这台机器，其余每台机器一个 tab，按最近有活动排序。**别的实例的库基本上只能读**——只有它自己那台机器会写它，所以那些 tab 里没有新增也没有改写；例外只有三处，且都不改写对方的记录：你按 `Ctrl+P` 时写的空 `.pin`、删除**已经翻篇**月份里的那几行（翻篇的库谁也写不着了），以及删对方**当月**记录时留下的空 `.del` 标记（见下「手动删除」）。

## 构建

本机不需要工具链，编译全在 GitHub Actions：

```bash
git add -A && git commit -m "..." && git push
```

`rust.yml` 跑 `windows-latest` → `cargo test` → `cargo build --release`，产出 `rust/target/release/ClipPlus.exe` 上传为 artifact。单文件、静态 CRT、SQLite 静态链接进去，不需要任何运行时。想在本机跑也一样：`cargo test` 就行。

同一个 exe 还会挂到 [latest release](https://github.com/issakk/cliplus2/releases/latest) 上，所以下载地址是固定的、不用点进 run 页面：**https://github.com/issakk/cliplus2/releases/latest/download/ClipPlus.exe** （每次 push 到 main 都重新发布一次；artifact 也还在，30 天过期）。

编译错误会直接以 check-run annotations 的形式挂在 commit 上，不用去下载 workflow 日志。

## 运行

1. 下载 [`ClipPlus.exe`](https://github.com/issakk/cliplus2/releases/latest/download/ClipPlus.exe)（固定地址，每次 push 到 main 会刷新），双击运行，托盘出现图标。
2. 按 `Win+Alt+V` 打开历史，输入即过滤，`↑↓` 选择，`Enter` 粘贴回原窗口，`Esc` 取消。弹窗**倒过来读**：搜索框在最下面，列表往上排到更旧的记录，所以搜索框上面那一行就是你刚复制的东西。打开时弹窗会主动抢到前台（否则收不到按键），**点别处失去焦点就自动收起**。
3. `Ctrl+C` 把选中的放回剪贴板但**不粘贴**（不切窗口、不注入按键），`Ctrl+P` 固定/取消固定，`Ctrl+Tab` 在实例 tab 之间切换，**焦点在列表里**时 `Del` 删除选中的记录（会先问一次；焦点在搜索框里时 `Del` 是删字）。**右键任意一行**就是这些操作的菜单：粘贴 / 复制 / 固定 / 删除 / 全选，每一行后面跟着它的快捷键。
4. 每条记录都带来源，弹窗第二行就是它：`文本 · 02-14 15:32 · 本机 · chrome.exe · 那个窗口当时的标题`。来源在**复制的那一刻**读，所以标题就是当时那个窗口的标题（最长存 120 字，行里放不下会省略）。**搜索默认只搜内容**，要按来源/标题/时间/机器/类型筛就加字段前缀（见下面「搜索」）。第一行是内容预览，一行放不下全部，所以多行的记录前面标 `[N 行]`（超过内联上限的记录只留开头，标 `[多行]`，完整内容在 `.bin`，第二行末尾会写明）。时间默认不带年份，**只有不是今年的**记录才写成 `2025-02-14 15:32`（越往上越旧，见到年份就是旧的）。
5. 多选：`Ctrl`/`Shift` 点行，或 `Shift+↑↓` 扩选，或 `Ctrl+A` 全选。多选后 `Ctrl+C` 按列表顺序**每行一条**拼成一段文本（图片在多项复制里会被跳过；只选一条时图片仍按图片复制）。
6. 弹窗最底下一块是「搜索框 + 实例 tab 条」，tab 就在搜索框正上方：「全部」是所有机器混排，「本机」只列这台机器，其余每台机器一个 tab。在 tab 那一行的空白处（或弹窗四周的留白，以及列表短于窗口时列表上方那块空出来的地方）按住左键可以直接拖动弹窗，**位置会被记住**（写进 `settings.json` 的 `PopupPosition`），下次打开还在那儿——不再跟着鼠标跑了。第一次打开（还没拖过）时，弹窗居中在你鼠标所在的那块屏幕上；如果记住的位置因为拔了显示器/改了分辨率跑到屏幕外，下次打开会被拉回最近那块屏幕里。弹窗**也可以拉伸**：鼠标贴到任意一条边或角就是缩放光标（右上角那两道短杠就是这个意思），拖它改大小，松手即记住（`settings.json` 的 `PopupSize`，单位是 96 DPI 下的逻辑像素，所以换到缩放不同的显示器上会等比放大而不是原样搬过去）；最小拖到「三行列表 + tab 条 + 搜索框」，比工作区还大的尺寸下次打开会被收回来。
7. 托盘右键是「设置…」「打开同步目录」「打开设置文件」「退出」。设置里的热键框点一下、再按组合键就录进去了，不用手写 `Win+Alt+V`。

界面统一用 Microsoft YaHei UI。弹窗是固定密度的一栏列表：字号 96 DPI 下 16 px，只跟显示器的缩放走（进程是 per-monitor DPI aware，所以 4K 屏上如果系统缩放还停在 100%，字就只有 100% 那么大）。设置窗口额外乘一个**你自己的字号**（`SettingsScale`，默认 125%，窗口里可改 50-300%）：那个窗口原本用 Windows 自己的 12 px，在 1080p/100% 下偏小，嫌小就调它、别去动系统缩放——设置窗口的字、行高、窗口大小会一起放大，100% 表示跟系统一样大。两个窗口**互不影响**。

首次运行自动在 `%OneDrive%\ClipPlus` 建立历史目录。没检测到 OneDrive 时退化为本地模式，功能完整，只是不跨机器。

## 搜索

输入即过滤，空格分开的每个词都要命中（`foo bar` = 同时含这两个词的记录，顺序和距离随便）。**默认只搜记录的内容**——要搜别的就加字段前缀，跟别的程序一样：

搜索框空着的时候，里面会用灰字列出这些字段名；右边那个 `?` 点开是同一份说明（带例子）。

| 前缀 | 搜什么 | 例 |
|---|---|---|
| （无） | 记录内容（前 512 字） | `hello`、`会议纪要` |
| `app:` | 来源程序，只存 exe 名 | `app:chrome` |
| `title:` | 当时那个窗口的标题（存 120 字） | `title:报表` |
| `time:` | 行上显示的那个时间 | `time:02-14`、`time:15:32`、`time:2025-02` |
| `machine:` | 机器：`本机` 或对方的机器 id | `machine:本机`、`machine:3f9a2c81` |
| `kind:` | 类型：`文本`/`图片`/`文件`，或 `text`/`image`/`files` | `kind:图片` |

可以混着用：`app:chrome title:报表 kind:text 年终`。不认识的词缀不算词缀——文本里写着 `12:30` 的照样能搜到。大小写不敏感（`APP:Chrome` 也行）。

搜不到的：512 字以后的长文本和图片内容（都在 `.bin` 里）、标题 120 字以后的、固定状态（`★`）。图片没有可搜的内容，用 `kind:图片` 列出来。

## 配置

`%LOCALAPPDATA%\ClipPlus\settings.json`。托盘右键 →「设置…」直接改（热键和记录开关**立即生效**，其余项下次启动生效）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `Hotkey` | `Win+Alt+V` | `Win`/`Ctrl`/`Alt`/`Shift` + 一个键（A-Z、0-9、F1-F24）。设置窗口里点进输入框**直接按下组合键**即可；至少需要一个修饰键，只有 F1-F24 能单独用（裸的字母键会吃掉全系统那个键） |
| `SyncRootOverride` | `null` | 手动指定历史目录，覆盖 OneDrive 自动探测 |
| `InlineTextLimit` | `8192` | 超过这个长度的文本拆到 `.bin` |
| `MaxBlobBytes` | `10485760` | 超过这个大小的图片直接丢弃，不进同步目录 |
| `RescanSeconds` | `60` | 兜底重扫周期（正常情况下靠文件监听，不会扫） |
| `SettingsScale` | `125` | 设置窗口的字号缩放百分比，见上。50-300，100 = 跟系统一样大。只影响设置窗口，弹窗不跟着变；改完保存即生效（窗口下次打开） |
| `PopupPosition` | `null` | 弹窗上次被拖到哪儿，`[x, y]`。程序自己写，不用手改；`null` = 还没拖过 |
| `PopupSize` | `null` | 弹窗上次被拉到多大，`[宽, 高]`，单位是 96 DPI 下的逻辑像素（按显示器缩放还原）。程序自己写，不用手改；`null` = 还没拉过 |
| `CaptureText` / `CaptureImages` / `CaptureFiles` | `true` | 分别开关 |
| `WriteBlobs` | `true` | 关掉 = 需要 `.bin` 的内容（超长文本、图片）直接丢弃，当没复制过，不会再产生 `.bin`。只留 512 字前缀又搜不到后面的内容，所以宁可整条不要 |
| `RetentionDays` | `0` | 自动删除本机 N 天前的记录。0 = 关闭；固定过的一律不删 |

日志在同目录的 `clipplus.log`。

## 固定与自动清理

**固定**（列表里 `Ctrl+P`）不写进剪贴板内容，也不写进别人的库——固定状态是**旁边多一个空文件**：

```
3f9a2c81/2026-02/clips.db     内容
3f9a2c81/2026-02/<stem>.pin   空的，存在即代表固定
```

还是旁路文件、而不是库里的一个字段，是因为你经常会想固定**别的机器**上的片段，而按规矩你只能写自己名下的东西；空文件在每台机器上内容完全一致，同时创建也不会被判为冲突。

这样它跟着网盘走：在笔记本上固定的片段，台式机上直接就能看到。两台机器同时创建同一个空文件，内容完全一致，任何网盘客户端都不会判为冲突。唯一的边缘情况是「A 取消固定的同时 B 在固定」，标记可能复活，再按一次 `Ctrl+P` 即可。

**自动清理**（设置窗口里填天数，默认 `0` = 关闭）只删**本机自己目录**下的东西，固定过的一律跳过。

它故意不碰别的机器的目录——「每台机器只写自己那份」是整套设计不冲突的根基，为了省点磁盘去破坏它不划算。代价是退役机器的历史永远不会被清理。

清理在启动后一分钟跑一次（等首次扫描落定），之后每 6 小时一次。

**手动删除**（焦点在列表里按 `Del`，或右键 →「删除」）对用户是同一件事：选中的那几条立刻从列表里消失，跟着库文件同步到每台机器，**删了找不回来**，所以会先问一次；多选就一次删一批。底下分两条路：

- **本机自己的记录，和已经翻篇的月份**：真的删——库里的行、同名的 `.bin` 和 `.pin` 一起走。本机的库只有我们在写；翻篇的库谁也不写、只被读，所以谁删都安全（两台机器同时删同一份，最多把其中一次删除丢掉，不会丢记录）。
- **别的机器当月还在写的记录**：那个库现在有写者，是对方那台机器，我们去写就成了第二个——网盘是**整个文件** last-writer-wins，而我们手里的副本可能是一小时前的，我们的版本一赢，对方这段时间新采集的记录会跟着一起消失。所以这几条**只留标记**：记录旁边一个空的 `<stem>.del`（跟 `<stem>.pin` 一个路子，空文件在任何机器上内容都一样，两台机器同时写也不会被判成冲突）。标记一落地，那条记录在**所有**机器上都不再显示；真正动刀的是主人——对方那台机器下次扫描（默认一分钟）读到标记，把行、`.bin`、`.pin` 和标记本身一起收走。

也就是说**删除谁都能提，行只有主人才删得掉**，「一次只写自己那份」这条底线没破。反过来，把那个 `.del` 空文件手删掉就等于撤销：只要对方还没清，记录就回来了。固定过的记录只会一直隐藏、不会被回收——`Ctrl+P` 是「它活得过清理」的承诺，标记不该打破它。

### 手动清理（设置 →「清理…」）

设置窗口底部新增一枚「清理…」按钮，打开一个专门的窗口，两件事各自独立、都是**先扫描出数字、弹窗确认后才动手**，执行在后台线程跑，扫的过程中界面不冻：

- **清理 .bin 大条目**——`.bin` 就是磁盘的去处（每张图最大能到单条上限，超长文本也整个在里面）。两个范围任选：**按时间**（清理 N 天以前的，0 = 全部）或**按条数**（只保留最新 N 个，0 = 全部）。命中的**整条删除**（行、`.bin`、标记一起走），不留空壳——图片没了字节就再也贴不出来，超长文本没了 `.bin` 就只能贴出前 512 字，那种「看着还在、贴出来缺肉」的条目比没有更糟。短文本和文件列表从不带 `.bin`，永远不受影响；固定的条目跳过；别机当月的条目从这里删不了，扫描会单独数出来。删完再复制同样的内容会照常重新入库。

- **清理重复文本**——同一段文本存了多份（两台机器都复制过最常见），每组**保留最新一份**，固定过的副本也保留（固定的承诺不因去重而破，所以带固定的组可能剩两条），其余删除。别机当月的那份照旧走墓碑，由主人机器下次扫描收走。

两个按钮共用一条底线：跟手动删除、自动清理一样，只动该动的东西——该跳过的跳过，该走墓碑的走墓碑，数字都会在确认框里写明。

## 已知限制

- **删别的机器当月的记录要绕一圈**：本机立刻不再显示（空 `.del` 标记），真身由那台机器下次扫描时收走。对方一直关着的话，那一行和它的 `.bin` 会留在磁盘上——但凡是读到过那个标记的机器，它都已经看不见了。
- **别的机器删掉的条目，要等它的库同步过来才消失**。库一变文件监听就刷新索引，条目立刻移除；对方那台机器当时关着的话，就要等下一次同步或下次启动。
- **搜索只覆盖前 512 字符**。超过的部分存在 `.bin` 里，为了不把异地图片和长文本全拉下来，索引进内存的只是前缀。
- **远端库第一次会被整份取到本地**。搜索要覆盖对方的全文就得打开对方的库，OneDrive 的「按需下载」会在首次扫描时把每个月的库拉下来（几 MB 一个）；代价比只读元数据高，但依然不会把异地几 G 的图片历史拉下来。
- **粘贴不到管理员权限的窗口**。程序以 `asInvoker` 运行，Windows 的 UIPI 会拦掉注入的按键。所有非提权剪贴板工具都一样。
- **同内容只存一条**。第二次复制同样的东西不会新建记录，也不会把旧条目顶到最前（行不原地改写，`at` 永远是它被复制的那一刻）。
- **实例 tab 超过 5 个会超出右边缘**。tab 条是按固定宽度画的（不测文字），两三台机器是常态；真到那天再改成测宽换行。
- **窗口拖到另一台缩放不同的显示器上不会立刻重排**（没处理 `WM_DPICHANGED`）：设置窗口要关掉重开才正常，弹窗的大小会被系统按新缩放改，字号和行高也得等下次打开。
- **弹窗的滚动条套的是系统的隐藏深色主题**（`win.rs` 的 `allow_dark_mode`/`dark_theme`：`SetWindowTheme` + 两个按序号导出的 uxtheme 开关）。非公开接口，某个 Windows 版本上可能静默失效，那时滚动条就还是浅色的系统样式——功能不受影响。
- **界面是深色占位风格**，没做主题适配。

## 结构

